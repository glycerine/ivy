# C4/C5: CLASS and SUBCLASS Must Use `createObject`

**Created:** 2026-03-24T23:55

## Context

The Go CLASS rule (`grammar_v17.y:866-886`) and SUBCLASS rule (`grammar_v17.y:888-902`) manually declare decls and iterate the module body directly into `$$`. Python instead declares TypeDecl (and VariantDecl for SUBCLASS) into the *module accumulator*, reorders decls to put them at the front, then calls `create_object()` which does `inst_mod` with prefix substitution. The Go code skips all of this, meaning class/subclass bodies don't get proper prefix rewriting.

## Python Source of Truth

### CLASS (`ivy_parser.py:737-747`)
```python
def p_top_class_symbol_eq_lcb_top_rcb(p):
    'top : top CLASS objsym objectargs EQ LCB optdotdotdot top RCB objectend'
    p[0] = p[1]
    scnst = Atom(This())
    scnst.lineno = get_lineno(p,2)
    tdfn = TypeDef(scnst, UninterpretedSort())
    tdfn.lineno = get_lineno(p,2)
    p[8].declare(TypeDecl(tdfn))
    p[8].decls = [p[8].decls[-1]] + p[8].decls[:-1]  # move TypeDecl to front
    create_object(p[0], p[3], p[4], p[8], get_lineno(p,3), p[7])
```

### SUBCLASS (`ivy_parser.py:749-761`)
```python
def p_top_subclass_symbol_eq_lcb_top_rcb(p):
    'top : top SUBCLASS objsym OF atype EQ LCB optdotdotdot top RCB objectend'
    p[0] = p[1]
    scnst = Atom(This())
    scnst.lineno = get_lineno(p,2)
    tdfn = TypeDef(scnst, UninterpretedSort())
    tdfn.lineno = get_lineno(p,2)
    p[9].declare(TypeDecl(tdfn))
    vdfn = VariantDef(scnst, Atom(p[5]))
    p[9].declare(VariantDecl(vdfn))
    p[9].decls = p[9].decls[-2:] + p[9].decls[:-2]  # move last 2 to front
    create_object(p[0], p[3], [], p[9], get_lineno(p,3), p[8])
```

### Key type note
- Python `Atom(This())` → In Go, `This()` has `.rep = "this"` so `Atom(This())` creates an atom with rep `"this"`. The Go equivalent is creating an Atom whose Rep is the This string. Looking at the current Go CLASS rule, it uses `ast.NewAtom("this")` which is correct for the name field. However, for `VariantDef`, Python passes `scnst` (which is `Atom(This())`), so in Go we use the same `scnst` atom.

### Key difference: `Atom(p[5])` in SUBCLASS
- Python `p[5]` is `atype` = a string (type name). `Atom(p[5])` creates an atom from it.
- Go `$5` is `ast.Node` (a `*ast.Symbol`). Need to extract rep: use `ast.NodeRep($5)` to get the string, then `ast.NewAtom(ast.NodeRep($5))`.

## Implementation

### Change 1: CLASS rule (`grammar_v17.y:866-886`)

**Current Go code:**
```go

{
    xtracer.Trace("parser.p_top__top_class_symbol_objectargs_eq_lcb_optdo ENTER (top)")
    $$ = $1
    objAccum := $8
    pref := $3.(*ast.Atom)
    // Declare type
    scnst := &ast.This{}

    td := ast.NewTypeDecl(tdfn)
    _ = scnst

    objDecl := ast.NewObjectDecl(pref)
    $$.declare(objDecl)
    $$.declare(td)
    for _, d := range objAccum.decls {
        $$.declare(d)

    // Python: stack.pop() equivalent
```

### Critical differences from current Go code

1. **Declare into `objAccum` not `$$`**: TypeDecl goes into the module accumulator (`$8`/`$9`), not the parent. `createObject` → `instMod` then rewrites and declares each into `$$`.
2. **Decl reordering**: TypeDecl (and VariantDecl) must be at the front of the module's decls before `instMod` processes them.
3. **`createObject` call**: Handles ObjectDecl declaration, Variable substitution for objectargs, and `instMod` prefix substitution — none of which the current code does.
4. **No manual ObjectDecl or decl iteration**: The current code manually declares ObjectDecl and iterates decls. `createObject` does all of this properly.
5. **SUBCLASS uses empty objectargs `[]`**: Not `$4` (which doesn't exist in SUBCLASS grammar — there's no `objectargs` token).
