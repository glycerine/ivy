# Plan: Fix missing empty mixin entries from Python defaultdict auto-creation

**Created**: 2026-04-02 17:45

## Context

`make golden` diverges at line 157394 in the `mixins` field. Go's mixins InsMap has 23 entries (the original mixin definitions from compilation), but Python's mixins defaultdict has 23 + ~65 additional entries, all with empty lists `[]`.

The root cause: Python's `mod.mixins` is a `defaultdict(list)` (ivy_module.py:51). When the main isolate processing loop iterates `mod.actions.items()` and reads `mod.mixins[actname]` (at ivy_isolate.py:70 via `add_mixins()`, and directly at line 1076), Python auto-creates empty entries for any action name not already in the dict. Go's `InsMap.Get2()` returns `(nil, false)` without creating entries.

The extra entries include:
- Mixer action names like `index.spec.next[after7]`, `rfn.abs.init[after231]` — generated by the grammar (`grammar_v17.y:1310,1319`)
- Regular action names like `ref.create`, `cfabric.step` — actions that happen to have no mixins

All are keys in `mod.Actions` that don't appear as mixees in any mixin definition.

## Root Cause Analysis

### Python (`ivy_isolate.py`)

Main processing loop (line 1036):
```python
for actname,action in mod.actions.items():
    ...
    new_actions[actname] = add_mixins(mod,actname,...)  # add_mixins line 70: reads mod.mixins[actname]
    ...
    for mixin in mod.mixins[actname]:  # line 1076: reads mod.mixins[actname]
```

Both reads auto-create empty entries for action names without mixins. Since `defaultdict(list)` is insertion-ordered (Python 3.7+), these entries appear after the existing compilation-time entries, in `mod.actions` iteration order.

### Go (`isolate/isolate.go`)

Main processing loop (line 510):
```go
for actname, act := range mod.Actions.All() {
    ...
    newActions.Set(actname, AddMixinsExt(mod, actname, ...))  // helpers.go:55: reads mod.Mixins.Get2(actname) — no entry creation
    ...
    if mixins, ok := mod.Mixins.Get2(actname); ok {  // line 572: no entry creation
```

Go never creates empty entries. The InsMap only contains the original compilation-time entries.

## Fix

**File**: `isolate/isolate.go`

At the top of the main action classification loop body (after line 511), add:

```go
// Match Python defaultdict(list) behavior: reading mod.mixins[actname]
// in the main loop auto-creates empty entries for actions without mixins.
// These entries are visible in CanonSnapshot serialization.
if _, ok := mod.Mixins.Get2(actname); !ok {
    mod.Mixins.Set(actname, nil)
}
```

This creates empty entries in `mod.Actions` iteration order, matching Python's defaultdict behavior exactly.

### Why this is sufficient

- ALL missing entries in the diff are action names that exist in `mod.Actions` (mixer names like `[after7]` from the grammar, and regular action names)
- The main loop iterates all of `mod.Actions`, so every missing entry gets covered
- Subsequent reads in `AddMixinsExt`, `makeBeforeExport`, `checkInterference`, and the export section all operate on action names that are already in `mod.Actions`
- The insertion order matches Python: existing entries first (from compilation), then new empty entries in `mod.Actions` order

1. `make golden` — the mixins divergence at line 157394 should be resolved
2. Python's extra entries (65+ empty `[]` entries) should now appear in Go's output
3. Insertion order should match (existing mixin entries first, then empty entries in `mod.Actions` order)
