# Plan: Port All Missing Python Grammar Productions to Go LALR

## Context

The Go LALR grammar (`lalr_logicparser/grammar_v17.y`) currently covers ~28% of the Python grammar (`ivy_parser.py`). It has complete formula/term parsing, basic action parsing, scenario parsing, and proof/tactic parsing. What's missing is the entire **declaration-level grammar** — all the `top : ...` productions that define modules, types, schemas, actions, interpretations, etc.

This port will bring the LALR grammar to full parity with the Python grammar, enabling cross-validation of all Ivy language constructs.

## Files to Modify

| File | Changes |
|------|---------|
| `ast/decl.go` | Add `Ivy` struct (top-level file container) |
| `lalr_logicparser/grammar_v17.y` | Add ~45 new tokens, ~40 new nonterminals, ~200 new productions |
| `lalr_logicparser/lalr_parser.go` | Add ~45 new token mappings in `Lex()` switch |
| `lalr_logicparser/grammar_v17.go` | Regenerated by `goyacc` |

## Approach

Almost all needed AST types already exist in Go. The concept-space types (`NamedSpace`, `ProductSpace`, `SumSpace`) are in `conceptspace/conceptspace.go`, `NativeAction` is in `actions/action.go:831`, and include/using use `ast.NamedDecl`.

**One new AST type needed:** `ast.Ivy` — the top-level file container. Python's `Ivy` class (`ivy_parser.py:241`) holds `.decls []`, `.defined`, `.modules`, etc. For the Go LALR grammar we need at minimum a struct with a `Decls []Node` field so that `top : top DECL` can accumulate declarations.

### Execution Strategy

The grammar will be built in sections, matching the Python file's organization. After each section, run `goyacc` to catch syntax errors early, then `go build` to catch type errors.

## Section 0: New AST Type

Add to `ast/decl.go`:

```go
// Ivy is the top-level file container, corresponding to Python's Ivy class
// (ivy_parser.py:241). It accumulates declarations parsed from an Ivy source file.
type Ivy struct {
    Base
    Decls []Node
}
func (iv *Ivy) Args() []Node           { return iv.Decls }
func (iv *Ivy) Clone(args []Node) Node { return &Ivy{Base: iv.Base, Decls: args} }
func (iv *Ivy) String() string         { return fmt.Sprintf("Ivy(%d decls)", len(iv.Decls)) }
// Declare appends a declaration to the file.
func (iv *Ivy) Declare(d Node) { iv.Decls = append(iv.Decls, d) }
```

## Section 3: Top-Level Declaration Grammar

Faithful to Python: `top` is an accumulating nonterminal. The base case is `top :` (empty, produces an Ivy() container), and all declarations are `top : top DECL`. This allows full file parsing, not just single-construct parsing.

```yacc
top:
    /* empty — base case, Python: 'top :' -> Ivy() */
    { result = &ast.Ivy{} }
    | top TOK_TYPE ...
    { /* append TypeDecl to $1 */ }
    | top TOK_ACTION ...
    | top TOK_SCHEMA ...
    // ... all other top : top DECL forms ...
    ;
```

The result is an `*ast.Ivy` (or `*ast.And` list) accumulating all declarations. The existing single-expression entry point moves to a separate `top_expr` alternative or is kept as a fallback for backward compatibility with current cross-validation tests.

To maintain backward compat with the existing formula/action/scenario cross-validation, keep those as alternatives:
```yacc
top:
    /* empty */       { result = &ast.Ivy{} }
    | fmla            { result = $1 }         // single formula (cross-val)
    | sequence        { result = $1 }         // single action seq (cross-val)
    | scenario        { result = $1 }         // single scenario (cross-val)
    | TOK_TACTIC ...  { result = ... }        // single tactic (cross-val)
    | TOK_PROOF ...   { result = ... }        // single proof (cross-val)
    // Accumulating declarations (faithful to Python)
    | top decl        { result = lalrAppendDecl($1, $2) }
    ;
```

The `lalrAppendDecl` helper appends a declaration to the Ivy container or wraps it. The `decl` nonterminal handles all declaration forms.

## Key Design Decisions

1. **`top` nonterminal**: Faithful to Python — uses `top : top DECL` accumulating pattern so the LALR grammar can do full file parsing. Single-expression alternatives kept for backward compat with cross-validation tests.

2. **Actions in `decl`**: Keep the existing action grammar in `sequence`/`action`/`simpleact`/`complexact` as-is. Only add missing action variants.

3. **AST types**: All needed types exist. Concept-space types (`NamedSpace`, `ProductSpace`, `SumSpace`) are in `conceptspace/` package — the grammar will import them. One new type needed: `ast.Ivy` (top-level file container with `Decls []Node`).

4. **NativeQuote**: The lexer handles NATIVEQUOTE specially (multi-line strings). The LALR parser can accept the token but semantic actions may be simplified.

5. **Version gates**: Only port v1.7+ productions since the grammar is `grammar_v17.y`.
