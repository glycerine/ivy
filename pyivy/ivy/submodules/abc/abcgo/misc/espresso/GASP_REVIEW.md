# Reduction and gasp heuristic review

Ported `reduce.go` and `gasp.go` with actual ordered reduction, SCCC recursion/special cases, candidate generation, irredundant extraction, last-gasp and super-gasp heuristics. All source entry points are implemented; expansion, all-primes, cofactor, partition, and irredundancy calls use the real neighboring Go implementations.

## Compactness, idiomatic Go, and readability pass

Retained the source's alternating reduction order and cube order dependencies. Cofactor lists borrow cover rows, so ordinary reduction changes subsequent reductions while gasp computes maximal reductions without replacing originals. Local names distinguish reduced candidates, original rows, raising bits, and free bits. Explicit loops replace pointer-array traversal. Each timed phase remains visible beside its source timing slot.

SCCC's debug recursion depth is an explicit recursive parameter rather than mutable static depth. The source's three-valued special-case return is retained as int32 (`1` resolved, `MAYBE` unresolved), since a Go bool cannot represent the original sentinel. Source-compatible paired cube operations remain visible rather than being obscured by generic callbacks.

## Independent bug review

Reviewed cofactor ownership and exclusion by row identity, sparse/dense masks, maximal reduction without replacement, PRIME/ACTIVE flags, source ordering alternation, empty-cube compaction, off-set activation, candidate deduplication, per-candidate reduction against a replaced original cover, and timing phase selection. Kept the source's unchanged-row copy in `reduce_gasp`: setting PRIME on its temporary reduction does not mutate the original row. The routine expects prime/irredundant input, as in C.

Recursive cofactor inputs are constructed before descending, so subsequent scratch-data updates cannot change their masks. Debug depth has no package-global recursion counter. No additional algorithmic fixes were needed after exhaustive-point and differential validation.

The existing intentional all-primes fix affects super-gasp: original C's no-active-blocker branch copies RAISE and drops FREESET, producing nonprime cubes. The Go implementation correctly uses RAISE | FREESET (see `EXPAND_REVIEW.md`). Tests retain raw-source super-gasp results and additionally rebuild a second reference with exactly that one-line fix. The reference generator documents this distinction rather than silently changing the original oracle.

## Evidence

- 120 seeded original-C fixtures compare exact ordered `reduce` and `last_gasp` rows, exercising both alternating reduction orders.
- Corrected-C super-gasp rows match exactly for all 120 fixtures. Raw C differs on 42 cases due to the documented all-primes bug.
- Each Go last/super result independently preserves on-set coverage modulo don't-cares, excludes every off-set point, contains only prime cubes, and has no redundant cube.
- 500 random mixed-valued covers compare SCCC against exhaustive complement-point unions and `reduce_cube` against exhaustive essential-point unions. Empty covers, full covers, redundant and partially essential cubes occur naturally.
- Combined set/geometry/cofactor/irredundancy/expand/sparse/matrix/minimum-cover/reduction/gasp race tests pass. Focused `go vet` passes.

Fixtures are generated by `test_vectors/generate_gasp_oracle.py`; ordinary Go tests use embedded JSON and require no C compiler. Package geometry and source ordering state remain package-scoped, as in the existing Espresso design; tests restore them and do not run geometry mutations in parallel. Full-directory integration remains separate from these explicit-file checks while other families are ported.
