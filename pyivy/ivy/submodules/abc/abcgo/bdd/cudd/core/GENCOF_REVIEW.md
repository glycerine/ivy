# Generalized cofactor review

## Ported behavior

`Cudd_bddConstrain` and `Cudd_bddRestrict` now use the core manager's canonical
ROBDD nodes, complemented edge handles, and current variable order. Both reject
foreign or closed-manager inputs. Constrain follows the paired cofactor care
branches and drops a variable when one care branch is zero. Restrict additionally
projects care-set variables absent from the function by ORing their cofactors,
then returns the smaller of the input and computed result as CUDD does.

The algorithms use operation-local memo tables, avoiding shared mutable cache
state. `dagSize` counts regular nonterminal nodes once and ignores terminal
nodes, matching the comparison needed by the restrict wrapper.

## Bug and compactness review

- Complemented care-set edges are handled through `DdManager.cofactors`, which
  complements both children consistently. The exhaustive test includes all
  complemented truth functions generated by the 3-variable truth tables.
- The top variable is selected by current level, while node reconstruction uses
  `InvPerm[level]`; tests run under identity and shuffled variable orders.
- Restrict's absent-support elimination is existential projection (OR of the two
  care cofactors), not universal projection. Exhaustive checks verify the care
  set relation and that the result introduces no support variables absent from
  the input function.
- Empty care sets return zero per CUDD's API. The complement identity is tested
  only for nonempty care sets, where it applies.
- Foreign-manager operands return nil before traversing nodes. Regressions cover
  both exported operations.

The exhaustive test checks all 65,536 pairs of 3-variable functions, eight
assignments per pair, under two variable orders. Full core race/vet checks are
